## 1. プロダクト概要

| 項目 | 内容 |
|---|---|
| 名称 | Pickle [仮]（ネーミング未確定） |
| 一言 | ピックルボールの**練習相手マッチング**アプリ |
| ターゲット | ソロ / 少人数のピックルボールプレイヤー |
| 価値提案 | スマホから **30秒で募集** → **DMで会話** → 当日プレイ |
| プラットフォーム | Mobile-first（🔸 ネイティブ or PWA/Web は未確定） |
| 提供範囲(MVP) | 施設を **THE PICKLE BANG THEORY (PBT / 本八幡) 1拠点に固定** |

### コアコンセプト
- 「投稿を見る → DMで会話が始まる」のシンプル動線に絞る
- 公開コメント機能は**あえて廃止**し、コミュニケーションを **DM 一本**に集約
- コート予約・空き状況は自前で持たず、PBTの **LaBOLA** 予約ページを埋め込み表示（Web=iframe / モバイル=WebView）

## 3. 画面別仕様

> **設計方針の転換（v0.4）**：構造化マッチング（タブ・フィルタ・レベル/人数/料金の選択式）をやめ、
> **自由記述の掲示板**に振り切る。日時・場所・レベル・人数・料金などは投稿者が**本文に自由記述**する。
> これに伴い「募集」タブを「**掲示板**」に改称。

### ① 投稿一覧（Board）
- 上部タブ・フィルタ chip は**廃止**（絞り込みなし）。
- **投稿カード**＝SNS/掲示板的なテキストカード：
  - 投稿者アバター・名前
  - 投稿時刻（例「2時間前」「昨日」）
  - **本文抜粋**（自由記述。日時・場所・人数・料金などはここに含まれる）
- **FAB**「＋ 投稿する」→ ③投稿作成へ
- カードタップ → ② 投稿詳細へ 🔸

### ② 投稿詳細（Post Detail）
- 投稿者情報（アバター / 名前 / レベル・DUPR 表記は任意 / 投稿時刻）
- **本文（自由記述）を大きく表示** — 日時・場所・人数・料金はすべてここに集約
- **CTA は DM 一本**：「投稿者にDMを送る」（全幅の主CTA）
- ※「参加表明」ボタン・「参加メンバー」表示は**廃止**（v0.4）

### ③ 投稿作成（Composer）
- ヘッダーに **"~ 30 sec"** 表示（入力の心理的負荷を予告）
- **自由記述テキストエリア1枚**に集約（項目選択は無し。SNS感覚で投稿）
  - プレースホルダ例：「今日 19:00〜21:00 / PBT コート2 ／ 中級ダブルス、あと1名募集！¥1,200/人・手ぶらOK🥒」
  - 補助テキスト「日時・場所・レベル・人数・料金など、自由に書いてください」
  - 文字数カウンタ（目安 300字）
- CTA「投稿する」

> **「投稿管理（私の投稿）」画面は廃止（v0.4）。** 主催者も通常の **DM一覧** から自分の投稿宛のやり取りを管理する。

### ④ コート（PBT空き状況 / LaBOLA埋め込み）※方針変更
- **施設・コートの管理はシステムで一切持たない**（場所はユーザーが投稿本文に自由記述）。
- PBT公式として、**PBTの予約（LaBOLA）を増やすために PBTの空き状況を見せるだけ**。
- 空き状況は**自前で登録・管理せず、LaBOLA を埋め込み/読み込みで表示**：
  - **Web**：LaBOLA予約ページの **iframe 埋め込み**（LaBOLA側が iframe 許可の場合。`X-Frame-Options` 要確認）。
  - **モバイル**：**`react-native-webview` でアプリ内表示**（トップレベル読み込みのため X-Frame-Options 制約を受けにくい）。
- CTA「**PBTで予約する**」（LaBOLAへ）。サブ導線「空き時間で募集を投稿する」→ 投稿作成。
- 🔸 **PBTのLaBOLA予約ページURL未確定**のため、現プロトタイプは**プレースホルダ表示**。URL確定後に iframe / WebView へ差し替え。
- 🔸 LaBOLA の「公式埋め込みウィジェット有無 / iframe許可 / 予約ページURL」を要確認。

### ⑤ DM一覧（DM List）
- スレッド一覧、各スレッド：
  - 名前 / 最終時刻
  - 最新メッセージプレビュー
  - **未読 = 背景色 + 赤バッジの2重強調**
- ※アバター・投稿コンテキスト（イベント名ピル）は**廃止**（v0.4）

### ⑥ DM 1対1（DM Chat）
- ヘッダー：相手情報（名前 / レベル / DUPR）※アバターなし
- メッセージバブル（自分 / 相手、日付区切り）
- 入力バー（＋ / テキスト / 送信）
- ※上部のピン留め投稿コンテキストは**廃止**（v0.4）

### ⑦ プロフィール（Profile）
- カバー：アバター / 表示名 / @handle / 自己紹介（一言）。右上に **「編集」** 導線。
- レベルカード：レベル + **DUPR スコア**（doubles）
- アカウント情報（メール / ログイン手段）、ログアウト
- ※3スタッツ（プレイ/マッチ/主催）・最近のプレイ履歴は**廃止**（v0.4）。レベル＋DUPRに絞ったミニマル構成

### ⑧ プロフィール入力・編集（v0.5 追加）
- **入力項目**：表示名（必須）/ レベル 初級・中級・上級（必須）/ DUPR（任意）/ 自己紹介・一言（任意）/ **アバター画像（任意・アップロード）**。@ハンドルは自動生成（編集対象外）。
- **オンボーディング `/onboarding`**：アカウント作成（メール/Google）直後に表示。レベル等を入力し「始める」でアプリへ。初回ログインで未設定なら必ず通す（`profileComplete` フラグで制御）。
- **編集 `/profile/edit`**：プロフィールの「編集」から遷移。既存値プリフィル → 保存で反映。
- 🔸 アバター画像：プロトタイプはクライアントで dataURL 化して localStorage 保持（サーバ保存なし）。本番は **Supabase Storage** 想定。

## 4. 主要なプロダクト判断（モックから読み取れる設計意図）

| 判断 | 意図 |
|---|---|
| 公開コメント廃止 → DM一本 | UIをシンプルに、コミュニケーションを集約 |
| DMは**投稿経由のみ**（突然DM不可） | スパム防止・健全性の担保 |
| マッチ終了 **30日後に自動アーカイブ** | DM一覧を整理された状態に保つ |
| 施設・コートの管理は持たない | 場所は投稿本文に自由記述。施設運営はシステム対象外 |
| コート＝PBTのLaBOLA空き状況を埋め込み表示のみ | PBT公式として予約(LaBOLA)を増やす導線。空き状況の自前登録・管理はしない |
| **DUPR** スコア採用（自己申告 / 任意連携） | レベルの信頼性向上 |
| **構造化マッチング → 自由記述掲示板へ転換（v0.4）** | 入力を1枚のテキストに集約し投稿ハードルを最小化。日時/場所/レベル/人数/料金は本文に自由記述 |
| 絞り込み（タブ/フィルタ）廃止 | 投稿数が少ない初期は一覧性を優先。掲示板的に流し見 |
| アバター表示は当面なし（v0.4） | 画像準備の前にテキスト中心で軽量に。名前ベースで識別 |
| 投稿管理画面を廃止（v0.4） | 主催者も通常のDM一覧で管理。画面数を削減 |
| 投稿詳細は参加表明・参加メンバーを廃止しDM一本（v0.4） | 「見る→DM」に動線を単純化 |
| ゲスト閲覧（掲示板・コートのみ）＋それ以外はログイン必須 | 入口のハードルを下げつつ、投稿/DM/プロフィールは本人性を担保 |
| 認証は Google ログイン＋メール登録 | まず Google を主動線に。プロトタイプではモック、本番は Supabase Auth 等で接続予定 |

### 認証・アクセス制御
| 範囲 | ゲスト | ログイン |
|---|---|---|
| 掲示板（一覧・投稿詳細の閲覧） | ✅ | ✅ |
| コート空き状況 | ✅ | ✅ |
| 投稿作成 / DM送信・閲覧 / プロフィール | ❌→ログイン誘導 | ✅ |

- 起動時は掲示板（公開）。保護アクション実行時に `/login?next=...` へ誘導し、認証後に元の画面へ戻す。
- ログイン手段：**Googleログイン**（主） / **メール会員登録**（表示名・メール・パスワード）。
- 登録/初回ログイン後は **プロフィール設定（オンボーディング）** を通す（レベル等）。プロフィールは後からマイページで編集可。
- 🔸 プロトタイプは認証をモック（localStorage保持）。本番は Supabase Auth（Google OAuth）想定。

## 5. 想定エンティティ（データモデルの当たり）🔸

> Supabase スキーマ設計の叩き台。詳細は別途。

- **User** … 表示名 / handle / アバター / レベル / DUPR スコア（施設会員連携は持たない）
- ~~**Facility / Court**~~ … **廃止**。施設・コートの管理はシステムで持たない（場所は投稿本文に自由記述、PBTの空き状況は LaBOLA を埋め込み表示するのみ）。
- **Post（投稿）** … 投稿者 / **本文（自由記述テキスト）** / 投稿日時 / ステータス（募集中/締切/終了）
  - 🔸 日時・場所・募集人数・レベル・料金は**本文に内包**し、構造化カラムは持たない方針（v0.4）。
  - 🔸 将来、本文から日時等を**任意抽出**して補助表示する余地はあり（MVP範囲外）。
- ~~**Application（参加表明）**~~ … **廃止（v0.4）**。参加表明・承認フローは持たず、interest 表明は **DM のみ**で完結。
- **DMThread** … 投稿に紐づく1対1スレッド（投稿者 ↔ DM送信者）/ 参加者2名 / アーカイブ日時
  - 投稿に対する反応は基本この DMThread が起点（「投稿経由のみDM可」）。
- **Message** … スレッド / 送信者 / 本文 / 既読状態 / 送信時刻
- ~~**Reservation（コート予約）**~~ … **廃止**。予約・空き状況は LaBOLA 側に委譲し、アプリは埋め込み表示と導線のみ。
