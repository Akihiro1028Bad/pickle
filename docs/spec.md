## 1. プロダクト概要

| 項目 | 内容 |
|---|---|
| 名称 | Pickle [仮]（ネーミング未確定） |
| 一言 | ピックルボールの**個人単発募集**アプリ |
| ターゲット | 20〜40代を中心としたソロ / 少人数プレイヤー、テニス・バドミントン・卓球経験者 |
| 価値提案 | スマホから **30秒で「誰か打ちませんか」を投稿** → **DMで調整** → 当日/今週プレイ |
| 提供範囲 | **全国対応**。初期の投稿密度づくりは PBT / 首都圏など特定地域から開始 |
| MVP方針 | イベント・大会・サークル管理ではなく、個人の1回限りの募集に絞る |

### コアコンセプト

- 「イベントを探す」ではなく **「今日・明日・週末に打てる相手を探す」**。
- 投稿を見る → DMで会話が始まる、のシンプル動線に絞る。
- 公開コメント、参加承認、決済、コート在庫管理はMVPでは持たない。
- 投稿は **最小構造化 + 自由本文**。全国化に必要な検索軸は項目化し、温度感や補足は自由に書けるようにする。

## 3. 画面別仕様

### ① 募集一覧

- 地域フィルタを表示。未選択時は全件、選択時は該当地域 + 全国向け投稿を表示。
- 将来フィルタ候補：今日 / 明日 / 週末、レベル感、募集人数、募集中のみ。
- 投稿カードに表示する情報：
  - 投稿者名 / アバター / レベル・DUPR（任意）
  - 投稿時刻
  - 地域 / 場所 / 日時 / 募集人数 / レベル感 / 表示時間
  - 本文抜粋
  - 公式 / おすすめ / 提携施設ラベル
- FAB「投稿する」から投稿作成へ。

### ② 投稿詳細

- 投稿者情報（名前、レベル、DUPR、自己紹介への導線）
- 募集条件（地域、場所、日時、募集人数、レベル感、ステータス）
- 本文全文（料金、持ち物、雰囲気、補足など）
- CTAは **DM一本**：「投稿者にDMを送る」
- 通報・ブロック導線を表示。

### ③ 投稿作成

投稿ハードルを下げつつ、全国検索に必要な情報だけ構造化する。

| 項目 | 必須 | 備考 |
|---|---:|---|
| 地域 | 必須 | 都道府県。将来は市区町村/エリアに拡張 |
| 場所・施設名 | 必須 | 自由入力。候補サジェストは将来対応 |
| 日時 | 必須 | 今日/明日/週末の判定に使う |
| 表示時間 | 必須 | 3時間 / 5時間 / 1日 / 3日 など |
| 本文 | 必須 | 300字目安 |
| 募集人数 | 任意 | 1人 / 2人 / 3人以上 |
| レベル感 | 任意 | 初心者歓迎 / 初中級 / 中級 / ガチめ |
| 料金目安 | 任意 | 現地払い前提。決済はMVP外 |

プレースホルダ例：

```text
今日 19:00〜21:00 / 本八幡のPBTで1人募集。
中級くらいで軽くゲームできる方、手ぶらOKです。
```

### ④ コート

- MVPでは予約在庫・空き枠を自前管理しない。
- 提携施設または外部予約ページへのリンクを表示する。
- 初期は PBT など投稿密度を作れる施設を上部に出す。
- CTA例：
  - この施設で予約する
  - この場所で募集を投稿する
- PBTの予約URLは要再確認。旧仕様のLaBOLA固定ではなく、現行の予約導線に合わせる。

### ⑤ DM一覧 / ⑥ DM 1対1

- DMは投稿経由のみ開始できる。突然DMは不可。
- スレッド一覧は未読を強調する。
- 投稿コンテキストは軽く表示する（日時・場所・相手名）。
- 30日後または投稿終了後一定期間で自動アーカイブ候補。
- 通報・ブロック・運営サポート導線を必ず持つ。

### ⑦ プロフィール

- 表示名 / @handle / 自己紹介
- レベル（初級・初中級・中級・上級など）
- DUPR（任意）
- アバター（任意）
- よく行く地域 / よく行く施設（任意）
- 通報/ブロック管理、ログアウト

## 4. 主要なプロダクト判断

| 判断 | 意図 |
|---|---|
| 全国対応 | フリーテキスト投稿でも地域を持てば全国化できる |
| 初期は地域集中 | 全国で薄く始めず、PBT/首都圏など投稿密度を作れる場所から立ち上げる |
| 個人単発募集に絞る | 既存のイベント/大会/サークル型サービスと正面衝突しない |
| 最小構造化 + 自由本文 | 投稿の軽さと検索性を両立する |
| DM一本 | 公開コメントや参加承認をなくし、会話開始までを短くする |
| DMは投稿経由のみ | スパム防止・健全性の担保 |
| 古い募集を自然に下げる | 当日/単発募集の鮮度を保つ |
| コート在庫は持たない | 予約/決済/空き状況の二重管理を避ける |
| 通報・ブロックはMVP必須 | UGC/DMアプリとして安全性とApp Store審査に必要 |

## 5. 認証・アクセス制御

| 範囲 | ゲスト | ログイン |
|---|---:|---:|
| 募集一覧・投稿詳細の閲覧 | ✅ | ✅ |
| コート/施設リンク閲覧 | ✅ | ✅ |
| 投稿作成 | ❌→ログイン誘導 | ✅ |
| DM送信・閲覧 | ❌→ログイン誘導 | ✅ |
| プロフィール編集 | ❌ | ✅ |

- 起動時は募集一覧（公開）。
- 保護アクション実行時に `/login?next=...` へ誘導し、認証後に元の画面へ戻す。
- ログイン手段：Google / Apple / メール。
- 初回ログイン後はプロフィール設定を通す。

## 6. 想定エンティティ

- **User**: 表示名 / handle / アバター / レベル / DUPR / 自己紹介 / よく行く地域 / よく行く施設
- **Post**: 投稿者 / 地域 / 場所・施設名 / 開始日時 / 終了日時 / 募集人数 / レベル感 / 料金目安 / 本文 / 表示期限 / ステータス / 投稿日時
- **FacilityLink**: 施設名 / 都道府県 / 市区町村 / 予約URL / 提携フラグ
  - 予約在庫・空き状況・決済は持たない。
- **DMThread**: 投稿 / 参加者2名 / 最終メッセージ / 既読 / アーカイブ日時
- **Message**: スレッド / 送信者 / 本文 / 既読状態 / 送信時刻
- **Report / Block**: 通報・ブロック対象 / 理由 / 状態 / 対応履歴

## 8. 未確定・要確認事項

1. 地域粒度：都道府県のみで始めるか、市区町村/駅/施設名まで必須にするか。
2. 日時入力：自然文 + 補助抽出にするか、最初から日時ピッカー必須にするか。
3. 料金：任意表示だけにするか、施設料金テンプレを持つか。
4. 成立KPI：DM開始、返信、実際のプレイ完了のどれを主指標にするか。
5. PBT予約URL：現行の正しい予約導線を確認する。
6. アプリ名：PBT色を残すか、全国サービス名へ寄せるか。
